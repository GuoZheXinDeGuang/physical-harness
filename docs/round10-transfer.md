# Round 10：零特权链跨任务零退化迁移，特权触发器静默失效

2026-08-20。

## 实验怎么设计的

直接把冻结策略跑到 Stack / PickPlaceCan 上是 **0% 成功** —— 它们的成功判据要求「放置」
（放到 B 上 / 送进料箱），而策略的四阶段日程只做「抓起来」。
按各任务自己的判据打分，测的是**策略缺的技能**，不是 critic。

三个任务真正共享的是**抓取**，而这正是演化出的 critic 检测的失败。
所以迁移实验打分的是共享子目标：**目标物体被举离起始高度 4cm 以上，且夹爪仍被撑开**。

三个场景：`lift`（cube）、`stack`（cubeA，cubeB 是干扰物）、`pickcan`（Can，形状/质量/摩擦不同）。
sd=0.020 下基线分别是 56.7% / 50.0% / 65.0%（dev 种子），held-out 上 48.5% / 46.0% / 55.0%。

## 零特权链：零重新搜索，零退化

在 Lift 上演化出的两条规则，**原样搬过去，一个字没改**：

```
observable.gripper_effort > 0.050879 for 2 steps, armed from t=59
observable.finger_gap     < 0.002232 for 1 steps, armed from t=63
```

| 任务 | 角色 | 基线 | 受治理 | 提升 | 修复 | 破坏 | p |
|---|---|---|---|---|---|---|---|
| lift | 源 | 48.5% | 76.0% | +27.5% | 55 | 0 | <1e-5 |
| stack | **迁移** | 46.0% | 74.5% | **+28.5%** | 57 | 0 | <1e-5 |
| pickcan | **迁移** | 55.0% | 79.0% | **+24.0%** | 48 | 0 | <1e-5 |

**没有退化。** Stack 甚至略高于源任务。每个任务 0 破坏。

原因是结构性的：两条规则都只读本体感受（夹爪关节速度、手指开度），
**没有任何一处提到物体**。「夹爪合拢但手里没东西」这个失败在物理上与你想抓什么无关。

## 特权触发器：同样的实验，静默失效

在同一批 lift dev 种子上，把预算放开到 1，搜出来的最佳特权触发器是：

```
privileged.object_z < 0.8215 for 1 steps, armed from t=62
```

| 任务 | 提升 | 触发次数 |
|---|---|---|
| lift（源） | +18.5% | 102 |
| stack | +18.0% | 107 |
| **pickcan** | **+0.0%** | **0** |

**0.8215 是 Lift 那张桌子的高度**，不是关于抓取的事实。
Stack 的 cubeA 恰好也在同一张桌子上，所以碰巧还能用。
罐子静止时高度不同，`object_z < 0.8215` 永远不成立 ——
**触发器不报错、不告警，就是一次也不触发。**

如果部署了它，你看到的是「这个技能在新任务上没效果」，而查不出为什么。

## 特权预算的完整实证论据

到这一轮为止，三条独立证据：

| 证据 | 来源 | 结论 |
|---|---|---|
| 检测质量 | round 3、round 9 | 零特权触发器的检测得分**高于**特权触发器（1.105 vs 1.095） |
| 真机迁移 | 消融曲线 | 特权感知 99.0% → 板载感知 sd=0.020 时 76.0%，退化可量化成曲线 |
| **跨任务迁移** | **本轮** | **特权触发器的阈值是关于世界的事实，换个场景静默变成 no-op** |

而且注意：特权触发器**连在自己的源任务上都更差**（+18.5% vs +27.5%）。

Zetta 的 critic 读 `privileged.dishwasher.rack.residual_to_success` 这类量，
README 用散文规定「不许当隐藏控制」。这一轮给出的是：
**特权不只是迁不到真机，它连迁到隔壁那个仿真任务都做不到，而且失败方式是静默的。**

## 顺带

`privileged.*` 特征需要一张查找表才能在不同任务里找到物体
（`cube_pos` / `cubeA_pos` / `Can_pos`），`observable.*` 不需要。
代码里的这个不对称本身就是论据 —— 已写进 `governor/features.py` 的注释。
