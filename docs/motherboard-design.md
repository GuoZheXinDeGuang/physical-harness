## Design

TWO-LAYER TARGET (v4.1). The repo converges to (L-exec) an execution harness whose skeleton holds ONLY decomposition rules, the JSON brief format, tool-call/mount conventions, and the execute-verify loop (dsh-style); and (L-evo) RSI — offline, independent — that drives L-exec as lab equipment for two jobs: (a) freeze skills+config, iterate harness config/params/rules; (b) auto-experiment in sim to learn skills that settle into the library WITH measured data. Everything else (VLM, nav, SLAM, percept, grasp, RL actions, robots, UI) is a card. Audit 1 localizes today's welds to exactly four places — EpisodeSpec defaults + spec_tabletop, harness_runtime dispatch tables, base_profile, and the governed/recovery half of RSI — plus two governor shims and the task vocabulary the base imports by fixed path. The kernel plumbing and the RSI statistics half are genuine LEGIT-BASE and are preserved untouched. The plan unwelds via manifest self-registration + base-owned fakes, hard-splits exec/evo by session mode, then PROVES each mechanism by reinstalling the existing assets as cards (W5 dogfood).

MODE MECHANISM (load-bearing v4.1 addition; revises M4 rung 3). Mode is a per-session property, default EXECUTION (fail-safe: real task runs never trigger RSI). `harness_runtime.py --mode {execution,evolution}` writes `<session-dir>/MODE` write-once (re-boot asserts a match → immutable across restart) and seals a `runtime.boot` row `{mode, skills_manifest=sorted(content-digest stems in skills_root), frozen_mount_plan_sha}` as row 0 of the hash-linked SessionLog — tampering with the recorded mode/manifest breaks chain verify(), which IS the audit (reuses existing chain_start/chain_step machinery, no new hash). Enforcement is one guard + one audit, both reusing existing machinery: (a) `_process` accepts `kind=="campaign"` ONLY in evolution mode, else rejects to failed/ with a `runtime.task_error` note (same rejection-not-neutralization pattern as the injected-key defense) — this IS the M4 rung-3 revision; (b) before each execution task, re-fold sorted(skills_root digest stems) and assert == boot skills_manifest — filenames already ARE content digests, so this is set-equality, catching any out-of-band mutation and making "immutable mid-session" machine-checked. One-way flow falls out: only evolution's `_copy_skills` writes sealed records; execution never writes skills_root and mounts only sealed SkillRecords (heldout_judgement_established=True) + the frozen profile. A real-actuator card (manifest `actuation:real`) is refused by this runtime — a different authenticated runtime, never a brief away. Doctor mapping: 体检 (Tier A/B) is mode-agnostic; 验货 (acceptance campaign) runs evolution-only and the seal it produces is the execution-mode admission ticket, so the doctor enforces the one-way flow at install time too. Test mapping: the base lane gets mode-gate unit tests on pure fakes; the stability soak gains an execution dimension (campaign brief injected → rejected, not crash) and an evolution dimension (campaigns accepted).

THE SEVEN DECISIONS. (1) DISCOVERY = directory scan of `plugins/*/manifest.toml` (DATA, parsed not imported — preserves profiles-declarative; entry_points rejected: they need a pip install per plugin, heavier, and buy nothing resolve_plan's last-writer-wins + provenance + duplicate-loud doesn't already give). base_profile() becomes a fold over installed manifests. The manifest carries everything currently welded: cap→ref+params mounts, third_party deps (replaces the _PLUGIN_THIRD_PARTY base-test table), task_bindings {task→policy/planner/catalogue-ref/oracles-ref/skill-specs} (replaces POLICY_BY_TASK + the fixed CATALOGUE/ORACLES import + SKILL_SPECS), campaigns {name→script} (replaces CAMPAIGN_SCRIPTS), `actuation:sim|real`, `needs_sim`. Authority preserved: a brief still names only a task STRING; the runtime resolves task→policy through the UNION of installed manifests at boot — adding a task = installing a plugin dir (a filesystem/operator act), never a brief; `_BRIEF_KEYS` reject-unknown stays. (2) plugin_doctor: `scripts/plugin_doctor.py <dir>` — Tier A mount-time shape (load_provider+isinstance, reusing Kernel.provide's check; refuse actuation:real), Tier B one canonical fake-episode per capability KIND via a kind→smoke dispatch table (~10 lines/kind cloned from existing self-checks), needs_sim gates real-sim smokes, per-kind determinism policy (deterministic-required for percept/stand-in-planner vs validated-untrusted for the LLM reasoner — handles qwen non-determinism). (3) 验货 = `scripts/acceptance_campaign.py`, a parameterized wrapper over the ALREADY-COMPLETE evidence machine (paired gate/blind twin/ablation/prereg hash), taking task/policy/stages/seed-block from the manifest claim; pass iff ≥1 promoted SkillRecord with heldout_judgement_established=True; the ~20-line pass/fail reader folds into `plugin_doctor --verify`. Seed allocation: `scripts/alloc_seeds.py` reads parse_ledger, returns the lowest unburned [lo,lo+N) — it SUGGESTS+the author reserves in STATUS.md; the runtime overlap-guard stays the enforcement (STATUS.md stays human-authored; auto write-back skipped until plugin volume makes it tedious). (4) tests = MARKERS not directories (the base/plugin line runs THROUGH 5 mixed files; a directory split forces cutting them apart): `tests/conftest.py` registers a `robosuite` marker + a collection hook auto-skipping when `find_spec("robosuite") is None`. Base fast lane = `pytest -m "not robosuite"` run ISOLATED (fresh process, card absent — never as a subset of a full green run, or it re-certifies the round-69 collection-order pollution as base). Gate snapshot before+after any base change: {pass count, skip count+reasons, wall time, AST boundary tests green}; the eval battery is the RSI-scoring-change gate, NOT the base lane. (5) "开机" with zero plugins = base-owned `harness/fakes.py` null providers (import only harness.contracts+stdlib) + `fakes_profile()`; `harness_runtime --drain` on a fake task brief completes to done/ and `pytest -m "not robosuite"` is all-green with the plugins/ dir empty; the fakes double as the doctor's fixtures. (6) zos: salvage doc FIRST (authority FSM, risk-derivation tree, permission ladder, verify AST-sandbox + resource-exhaustion lesson, not-measured discipline), sever refs, tombstone+tag; real-robot ACT half explicitly SHELVED (harness stays sim-only — matches W5's plugin list omitting real-robot; a real embodiment becomes a future actuation:real card + authenticated runtime, refused by the sim runtime, consistent with v4.1). (7) Ordering below, with W5 dogfood as the proof of each mechanism.
