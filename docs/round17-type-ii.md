# Round 17：策略时钟，以及门禁的一次第二类错误

2026-08-20。

## 做了什么：critic 只在策略拥有控制权时求值

Round 16 暴露的缺陷：第一代之后轨迹混合了「策略驱动」和「脚本恢复驱动」的步，
搜索分不清，于是第二代提出了一个武装在 **t=129** 的候选 —— 那在恢复程序内部，
而克隆策略自己的时钟只有 100 步。

改法比打补丁更彻底：**critic 治理的是策略，所以它在恢复动作拥有控制权时既不观察也不触发，
那些步也不进轨迹。** `arm_after` 因此计的是**策略拥有的步**，这也是唯一在不同长度的
episode 之间含义一致的时钟。t=129 那一类伪影从结构上不可能再出现。

顺带被回归测试抓到一个变量遮蔽：`for k in consec: consec[k] = 0`
把策略步计数器 `k` 覆盖成了 rule_id 字符串。

## 代价：+29.0pp → +22.5pp，链缩到一条规则

```
gen 1  running_min(finger_gap) < 0.004473 @58   +14.2%  fixed=17 broken=0  p=2e-5   -> 提升
gen 2  gripper_effort > 0.029791 dwell3 @58     +5.8%   fixed= 9 broken=2  p=0.065  -> 拒绝
```

held-out：**48.5% → 71.0%，+22.5pp**（旧语义 +29.0pp）。

## 然后我查了原因，结果是反直觉的

先试了一个假设：旧语义下 critic 在恢复期间仍在求值，所以第二条规则实际提供的是
**第二次修复尝试**而不是第二个检测器。把修复预算做成显式旋钮验证：

```
max_invocations=1 / 2 / 3   全部 +22.5pp，逐位相同
```

**假设错了。** 换一个能直接分辨的实验 —— 把两个语义各自选出的 g2 都放进新语义跑：

| 组合 | held-out |
|---|---|
| g1 单独 | +22.5pp |
| g1 + **旧语义**选的 g2 | +22.5pp（现在毫无贡献） |
| g1 + **新语义**选的 g2（**就是被拒绝的那条**） | **+29.0pp** |

**门禁拒绝了一条在 held-out 上值 +6.5pp 的候选。** 这是一次真实的第二类错误。

## 关于这次测量本身的纪律

我是**事后**花了一次 held-out 测量才看到这件事的。两点必须说清楚：

1. **那个 held-out 区块为这个问题烧掉了。** 它不能再当作这条候选的干净证据。
2. **我不会因此提升 g2。** 那就是用测试集做选择 —— 正是这套方法论存在的意义所在。
   脚本策略在新语义下的成绩**就是 +22.5pp**，那是按预注册协议真正赚到的数字。

## 真正的教训是统计功效，不是门禁太严

9 修复 / 2 破坏在 n=120 上的精确 McNemar p = 0.0654。同样的比例放大：

| dev 样本量 | 判定 | p |
|---|---|---|
| 120（实测） | 9/2 | 0.0654 ❌ |
| 180 | 14/3 | 0.0127 ✅ |
| 240 | 18/4 | 0.0043 ✅ |

**后面的世代需要比前面更多的 dev 种子**，因为残余效应量本来就更小。
用固定的 `rollout_count` 跑所有世代（Zetta 的 `EvolutionProtocol.rollout_count=50` 也是固定的），
等于让后期世代系统性地功效不足。

这条比「门禁又拒了一个坏候选」有价值得多 —— 今晚前面几轮全在庆祝门禁拒对了东西，
这一轮量化了它拒错的代价。

## 保留新语义的理由（不是按分数选的）

- 它从结构上消除了 t=129 那一类伪影，而不是靠事后过滤
- 策略时钟是唯一在不同长度 episode 之间含义一致的时钟
- 恢复动作是有界的脚本程序，不需要 critic 监督（Zetta 的设计里恢复期间的权威是 Role1，不是 critic）
- 丢掉的 +6.5pp 不是语义拿掉了能力（旧语义选的 g2 在新语义下贡献为零），
  而是一次可以靠加样本量修复的功效不足

## 下一个 frontier

1. **按世代递增 dev 样本量**：`rollout_count` 不该是常数。可以按残余失败数定，
   或者对每代做功效计算。这是本轮直接得出的。
2. **recovery 库**（round 16 的结论仍然成立）：42/120 的失败被检测到却修不好。
