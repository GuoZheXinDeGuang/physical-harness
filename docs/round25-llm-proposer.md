# Round 25：LLM proposer 跑通了，并且暴露了我自己的目标函数没被验证过

2026-08-20。Frontier 里最后一条没碰过的。

## 立场：proposer 是不可信输入，不管谁写的

`governor/proposer.py` 定义接缝，两个 provider：

- **`SearchProposer`（参考实现）**：确定性搜索，零网络零密钥。项目里所有结果都是它产出的。
  **一个没有网络和密钥就跑不起来的循环，是一个无法复现的循环。**
- **`LlmProposer`**：把统计摘要交给模型，拿回文本，**只有通过和确定性 proposer 完全相同的校验才成为 Rule**。

校验包括：特征必须在已发布目录里、特权必须符合预算、操作符和归约必须已知、
数值必须有限且在范围内、恢复策略必须在库里。**「模型说的」不缩短这条路径。**
这和 dsh 对待工具参数、Zetta 对待 Stage-2 候选是同一个立场：**边界是 schema，不是作者。**

对抗测试覆盖了真实模型会犯的每一种错：编造特征、越预算取特权特征、返回散文而非 JSON、
NaN 阈值、dwell=0、arm_after 越界、未知恢复策略。共 74 个测试全绿。

brief 只带**统计摘要**（2186 字节），不带原始 episode，而且只列出轨迹里真实存在的特征 ——
轨迹里有什么本身就受隔离限制，遍历整个 registry 会去够一个隔离已经挡掉的列。

## 端到端（真仿真，零 API 成本）

mock transport **真的读 brief** 再挑：取最强分离行、圆整阈值、在峰值前两步武装。
这是一个称职的模型拿到这份 brief 会做的事。

| proposer | 候选 | held-out（全新区块 1600-1799，n=200） |
|---|---|---|
| mock 模型 | `running_range(finger_gap) < 0.005 @85` | **+31.5pp**，63 修 **0 破** |
| 确定性搜索 | `running_min(finger_gap) < 0.0129 @58` | +26.0pp，53 修 1 破 |

**那个天真的挑法赢了 5.5pp。**

## 为什么：earliness 权重从没被验证过

搜索的目标函数是我手写的：

```python
score = recall - 1.2 * fp + 0.25 * (lead / n_steps)
```

那个 **0.25 的 earliness 权重**偏好早触发的候选。mock 模型不看时机，只看分离强度，
于是选了一个**晚得多**（t=85 vs t=58）但更准的触发器。

Round 3 里正是这个权重让 `gripper_effort` 赢过 `finger_gap`，
当时我把它当成「搜索比人强」的证据之一。**它从没被标定过，而这里它值 −5.5pp。**

## 不过分解读

这是**一个** held-out 区块上的**一次**比较（两臂同时评分，是合法的单次使用）。
不足以说「LLM proposer 更好」——它只说明**我的目标函数权重是个未经验证的手调常数**，
而一个更简单的准则（取最强分离）在这里更好。

下一轮该做的是扫这个权重，而不是换 proposer。

## 说清楚这一轮没做什么

**没有调用任何真实 LLM API。** 整条路径是对着脚本化 stand-in 验证的，
沿用 dsh 测 agent loop 的做法（`packages/test-support/llm-mock-server`）。
接上真模型只需要把 `transport` 换成一个 HTTP 调用 —— 但那会引入网络、密钥和方差，
而这三样正是「零外部 API 是参考路径不是回退」这条设计要避免的。
