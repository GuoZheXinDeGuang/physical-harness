# Round 21：为一个不存在的失败模式造了一个原语

2026-08-20。Round 19 认定天花板在修复原语，唯一的路是写一个更强的。这一轮写了一个，
按纪律测了，没通过 —— 然后查出**前提本身是错的**。

## 造了什么

`governor/servo.py`：两个接触反馈原语，全部只读本体感受（零特权）。

- **`ServoDescend`**：命令稳定下降速度，盯末端实际高度。还在往下推却不再下降 = 下面有东西。
- **`ServoClose`**：合拢到手指停止移动，然后按最终开度判断有没有握住东西。

`RecoveryActor` 改成执行**段序列**：固定段重放阶段，伺服段自己决定长度。
新策略 `servo_regrasp` 把两者混用 —— 接近保持开环，真正需要接触的那一段不再猜高度。

## 按纪律测，没通过

| 切片 | 结果 |
|---|---|
| 选择切片 2000-2089 (n=90) | servo_regrasp **+13.3%** vs 现役 +11.1% → 领先 |
| 不相交门禁切片 2090-2179 (n=90) | +3.3%，修 3 破 **0**，**p=0.25** → 不通过 |
| **确认性切片 2200-2649 (n=450)** | **+1.8%，修 19 破 11，p=0.20** → **不采纳** |

确认性切片是**预注册**的：按前面观测到的不一致产出率（3/90）和 80% 功效需要的 15 对，
在跑之前定好 450 个种子。看到 p=0.25 之后去扩那个切片会是 optional stopping；
另起一个全新切片做后续确认是正常的。

**注意前面那个「修 3 破 0」的完美战绩是小样本运气** —— 功效充足后是 19 修 11 破。

## 然后查出前提是错的

```
percept z-error: mean |dz| = 0.00000
```

`_percept_object` 扰动的是 x 和 y，**z 分量恒为 0**：

```python
true + np.array([rng.normal(0, sd), rng.normal(0, sd), 0.0])
```

**朴素修复下降到的是真实高度。** `ServoDescend` 消除的是一个不存在的误差。
我在造它之前从没验证过这个前提。

## 但孤立探针里 servo 确实更好

从同一状态分别跑两种修复，各 60 次：

| | regrasp | servo_regrasp |
|---|---|---|
| 夹爪握住东西 | 40/60 | **47/60** |
| 物体被抬起 | 40/60 | **47/60** |
| 最终手指开度 | 0.0319 | 0.0367 |

既然 z 没有误差，这 +7/60 只可能来自 **`ServoClose`** —— 合拢到手指停止，
而不是固定合拢 14 步。这部分不受前提错误影响，仍然有存在理由。

但它没有在配对门禁上兑现，所以**不采纳**。

## 修正后的方向

噪声在**桌面平面**里，不在高度上。所以匹配这个失败的原语应该是
**接触引导的横向搜索**（碰到之后沿平面探），不是垂直的。

代码里那句错误的论断已经改掉，并把整段错误留在 docstring 里 —— 这个错误值得留着。

## 这一轮的教训

**在造一个东西之前，先验证它要解决的问题存在。** 我有现成的手段验证
（一行 `percept - true`），花了 15 分钟造原语、6 分钟跑三轮门禁，
而验证前提只要 30 秒。round 19 的诊断没错，错的是我把「感知不准」笼统当成了「高度不准」。
